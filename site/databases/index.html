    라이선스 GPL + 상용 BSD GPL

    복제 비동기/반동기 동기/비동기 비동기/반동기

    캐싱 패턴¶

    패턴 설명 사용 사례
    Cache Aside 애플리케이션이 캐시 관리 일반적인 캐싱
    Read Through 캐시가 DB 조회 읽기 중심
    Write Through 캐시와 DB 동시 쓰기 일관성 중요
    Write Behind 캐시만 쓰고 비동기 DB 저장 성능 중요

    JPA 관계 매핑¶

    관계 유형¶

    erDiagram
    USER ||--o{ ORDER : places
    ORDER ||--|{ ORDER_ITEM : contains
    PRODUCT ||--o{ ORDER_ITEM : included_in
    CATEGORY ||--o{ PRODUCT : has

    USER {
        Long id PK
        String email
        String name
    }
    ORDER {
        Long id PK
        Long userId FK
        LocalDateTime createdAt
    }
    ORDER_ITEM {
        Long id PK
        Long orderId FK
        Long productId FK
        Integer quantity
    }
    PRODUCT {
        Long id PK
        Long categoryId FK
        String name
        BigDecimal price
    }
    CATEGORY {
        Long id PK
        String name
    }

    1:N @OneToMany User → Orders

    성능 최적화¶

    쿼리 최적화¶

    -- 인덱스 생성
CREATE INDEX idx_user_email ON users(email);
CREATE INDEX idx_order_user_created ON orders(user_id, created_at);

-- 실행 계획 확인
EXPLAIN ANALYZE SELECT * FROM orders WHERE user_id = 1;

    N+1 문제 해결¶

    // ❌ N+1 문제 발생
List<User> users = userRepository.findAll();
users.forEach(u -> u.getOrders().size()); // 각 user마다 쿼리

// ✅ 페치 조인으로 해결
@Query("SELECT u FROM User u JOIN FETCH u.orders")
List<User> findAllWithOrders();
