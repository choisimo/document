# 개발 프로젝트와 워크스페이스 전환

Project Manager에 관한 보관 노트에는 확장 게시자·정확한 식별자·버전이 없다. 따라서 그 노트의 설정 키나 단축키를 검증된 설치 절차로 복사하지 않는다. 설치된 확장의 명령 팔레트와 설정을 확인한 뒤 다음 작업 모델을 적용한다.

| 대상 | 맡기는 역할 | 별도 확인 |
| --- | --- | --- |
| 프로젝트 즐겨찾기 | 폴더·workspace 위치를 찾아 전환 | 경로 존재, 원격 환경, 이름·태그 |
| Workspace | 함께 열 폴더와 작업 범위 | 상대 경로, workspace 설정 |
| 프로필·확장 | 편집기 도구와 사용자 설정 | 프로젝트 실행 의존성과 구분 |
| 빌드·디버그 구성 | 실제 compiler·runtime·작업 디렉터리 | IntelliSense 설정과 실제 빌드가 일치하는지 |

## 전환 절차

처음에는 실제 존재하는 프로젝트 하나만 등록한다. 이름·태그를 업무 기준으로 정하고 닫은 뒤 다시 열어 같은 폴더인지 확인한다. 원격 환경에서는 로컬 경로가 원격 머신의 경로와 같은 뜻이 아니다.

여러 폴더를 묶을 때에는 각 폴더의 빌드 명령과 의존성 위치를 기록한다. “프로젝트를 열었다”는 사실은 virtualenv, JDK, compiler, DB가 준비됐다는 뜻이 아니다. 터미널과 디버거에서 실행 경로·버전·입출력을 각각 확인한다.

## 이동·공유·복구

저장 위치를 바꾸면 프로젝트 목록, workspace의 상대 경로, task의 작업 디렉터리를 함께 확인한다. 기존 설정 사본을 보존하고 작은 범위에서 바꾼다. 프로젝트 목록은 개인 절대 경로나 비공개 저장소 이름을 포함할 수 있으므로 그대로 공개하지 않는다.

다른 환경에 전달하는 문서는 `workspace/frontend`, `workspace/backend` 같은 예시 경로와 필요한 설정의 역할만 설명한다. 자동 환경 전환이나 확장 간 동기화를 설치된 도구에서 확인하지 않았다면 지원 기능으로 쓰지 않는다.
