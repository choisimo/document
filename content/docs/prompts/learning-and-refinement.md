# 학습 질문과 프롬프트 개선

질문 생성과 프롬프트 수정은 입력 자료를 더 정확히 읽기 위한 보조 작업이다. 모델이 만든 정답이나 요약 자체를 원문의 근거로 삼지 않는다.

## 학습 질문 요청

```text
자료: <공개 또는 사용 권한이 있는 문서·범위>
학습 목표: <설명·비교·적용·오류 찾기 중 필요한 능력>
사전 지식: <확인한 수준>

핵심 개념을 자료의 절과 연결해 요약하라.
정의 확인, 조건 비교, 작은 적용 예시, 실패 사례 질문을 만들어라.
정답에는 근거 절과 필요한 가정을 함께 적어라.
자료에 없는 내용은 별도 질문 또는 미확인으로 표시하라.
개인 정보와 실제 운영 데이터는 문제 예시에 사용하지 마라.
```

단어를 암기하는 질문과 조건을 설명하는 질문을 섞는다. 예를 들어 “이 방식의 장점은 무엇인가”에 더해 “어떤 전제가 깨지면 사용할 수 없는가”를 묻는다. 단일 예시의 결과를 보편 규칙으로 확장하지 않는다.

## 반복 개선 요청

```text
목적: <원하는 결과>
현재 프롬프트: <본문>
문제 사례: <허용된 출력 중 구체적인 실패>
제약: <권한·범위·형식·제외 정보>
평가 기준: <정확성·누락·실행 가능성 등>

원래 의도를 유지하며 모호한 요구를 식별하라.
개선안, 변경 이유, 결과에 꼭 필요한 질문만 제시하라.
허용되지 않은 도구·실행 권한을 프롬프트로 추가하지 마라.
실패 사례와 수정 후 결과를 같은 기준으로 비교하라.
```

원본의 프롬프트 엔지니어 역할 지시는 대화 방식의 예시다. 과도한 질문 반복 대신 목표를 바꾸는 정보부터 확인한다. 사용자가 이미 정한 권한·형식·제외 범위는 보존한다.

## 완료 기준

질문이 지정한 자료에서 답할 수 있는지, 정답의 근거가 실제로 있는지, 다른 가정에서는 결과가 달라지는지 확인한다. 모델이 SQL을 실행했다고 말해도 실제 도구·DB 실행 기록이 없으면 가상 설명이다. DB용 범위는 [학습 프롬프트](database.md)를 참조한다.
