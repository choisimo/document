# 호스트·컨테이너·로그 시간 진단

시계 동기화는 호스트의 시점을 맞추고 시간대는 그 시점을 표시하는 규칙이다. 로그가 늦게 보이거나 다른 시간에 찍힌다고 시간대부터 바꾸지 않는다.

## 호스트와 컨테이너 비교

```bash
timedatectl status
timedatectl show -p NTPSynchronized -p NTP
date --iso-8601=seconds
date -u --iso-8601=seconds
```

위 `date` 옵션은 GNU date 기준이다. 컨테이너는 설치된 도구의 지원 옵션부터 확인한다. 컨테이너가 호스트 커널 시계를 공유하는 것과 이미지의 표시 시간대 설정은 별개다. `/etc/localtime` 마운트나 `TZ` 변경은 시계 오차 자체를 교정하는 절차가 아니다.

현재 사용하는 동기화 구현을 확인하고 여러 NTP 서비스를 동시에 추가하지 않는다. 운영 중 시계 변경은 로그 순서·만료·스케줄에 영향을 줄 수 있으므로 변경 전 상태와 영향 범위를 기록한다.

## 로그 한 건을 끝까지 추적

1. 비민감한 시험 이벤트 하나의 발생 시각과 offset을 기록한다.
2. 원본 로그의 시각이 생성 시각인지 수집 시각인지 확인한다.
3. 수집기의 읽기 위치·파싱 오류·전송 오류를 확인한다.
4. 저장소에서 그 시각을 포함하는 **절대 UTC 범위**로 조회한다.
5. 결과의 저장 시각과 원본을 비교하고 마지막에 화면의 표시 시간대를 확인한다.

| 관찰 | 다음 확인 |
| --- | --- |
| 호스트 UTC 자체가 다름 | 동기화 상태·기준 서버·오프셋 |
| UTC는 같고 표시만 다름 | 앱·컨테이너·UI의 시간대 |
| 로그 시각은 맞지만 검색 안 됨 | 라벨·조회 범위·수집 위치·파싱 |
| API와 로그만 서로 다름 | 직렬화·DB 세션·로그 formatter |

시간대를 일괄 변경하지 말고 잘못 해석된 계층만 수정한다. 복구 뒤 시험 이벤트가 예상 라벨과 범위에 나타나고 중복·누락이 없는지 확인한다. 서버 시간이 비슷해 보인다는 것만으로 로그 수집 성공을 판정하지 않는다.
