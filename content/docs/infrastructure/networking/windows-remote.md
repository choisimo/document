# Windows 인터페이스·WOL·SSH 점검

Wake-on-LAN(WOL), 네트워크 경로 선택, OpenSSH 접속은 서로 다른 상태를 확인하는 작업이다. 보관 메모의 일반 진단 절차만 복구하며 실제 장치 주소·MAC·계정·망 구성은 포함하지 않는다.

## 인터페이스 우선순위

```powershell
Get-NetIPInterface
```

대상 인터페이스와 주소 계열, 자동 metric 여부, 실제 경로를 함께 확인한다. metric 하나를 낮췄다는 이유만으로 모든 목적지의 경로가 바뀌었다고 가정하지 않는다. 변경이 필요하면 이전 값과 콘솔 복구 방법을 보존하고 대상 인터페이스만 바꾼 뒤 실제 연결을 시험한다.

## WOL의 단계별 성공

| 단계 | 확인할 근거 |
| --- | --- |
| 하드웨어·펌웨어 | 해당 보드·NIC·전원 상태가 깨우기를 지원하는지 |
| OS·드라이버 | 매직 패킷과 전원 관리 설정 |
| 패킷 전달 | 승인된 같은 네트워크 범위에서 전달되는지 |
| 실제 기동 | 대상 장치가 정한 시간 안에 깨어나는지 |
| 서비스 준비 | 기동 후 승인된 서비스가 응답하는지 |

매직 패킷 전송 함수가 성공해도 대상 기동이 성공한 것은 아니다. 같은 네트워크에서 먼저 검증하고 인터넷 전달을 위해 무제한 broadcast나 포트 공개를 켜지 않는다. 전원 상태별 동작은 장치마다 다르다.

## SSH는 별도 기능

OpenSSH Server 설치 여부와 서비스·유효 설정·방화벽을 확인한다.

```powershell
Get-Service sshd
Get-NetFirewallRule -Name OpenSSH-Server-In-TCP
sshd -t
```

계정 종류에 따라 공개 키 파일의 적용 경로가 다를 수 있다. 유효 설정과 로그로 확인하고, 비밀번호 인증을 제한하기 전에 새 세션에서 키 로그인을 시험한다. 기존 관리자 세션과 로컬 콘솔을 복구 수단으로 유지한다.

완료 보고에는 기동 성공, 네트워크 연결, SSH 인증·권한을 각각 기록한다. 진단 출력에 있는 개인 계정·주소·장치 식별자는 공개 보고서에서 제거한다.
