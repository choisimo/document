# BM25와 어텐션의 라우팅/집중 차이 학습 및 기록 노트

> 💡 **이 글을 쓰는 이유:** BM25와 어텐션은 둘 다 "중요한 정보에 집중한다"는 인상을 주지만, 같은 기술이 아니다. BM25는 통계 기반 희소 검색이고, 어텐션은 신경망 안에서 Query-Key-Value 관계를 가중치로 계산하는 메커니즘이다. 둘을 같은 말로 섞지 않기 위해 작동 방식, 상태, 실패 조건을 분리해서 기록한다.

---

## 1. 왜 필요한가? (Pain Point & Motivation)

* **이 개념이 구원해 줄 문제:** "BM25도 라우팅이냐", "어텐션도 검색이냐" 같은 질문에서 기술 계층을 섞어버리는 문제를 막는다.
* **대안들의 한계 (기존의 똥떵어리들):** 둘 다 중요도를 다룬다는 이유만으로 같은 메커니즘이라고 말하면, 역색인 기반 검색과 딥러닝 내부 가중치 계산을 구분하지 못한다. 그러면 SPLADE 같은 학습 희소 검색 모델을 볼 때도 무엇이 BM25이고 무엇이 어텐션의 역할인지 흐려진다.

## 2. 현재 나의 상태 (Baseline)

* **여기까진 안다 (익숙한 땅):** BM25는 단어 빈도와 역문서 빈도로 점수를 계산하고, 어텐션은 Query, Key, Value의 벡터 관계로 가중치를 만든다.
* **뇌정지 오는 부분 (안개 속):** BM25가 역색인을 통해 관련 문서만 보게 만드는 효과가 있어서, 겉으로는 hard attention이나 routing처럼 느껴진다.
* **아직은 무리 (워너비):** "효과가 비슷하다"와 "메커니즘이 같다"를 분리해서 설명해야 한다.

## 3. 도달하고 싶은 목표 (Target State)

* **이 글을 끝내고 할 수 있는 일:** BM25, 어텐션, SPLADE를 각각 다른 층위의 기술로 설명하고, 어느 경우에 라우팅이라는 표현을 써도 되는지 판단할 수 있다.
* **이것만은 건지자 (최소 성공 기준):** BM25는 점수 함수이고 역색인은 후보 검색 자료구조임을 구분한다. 후보를 좁히는 효과는 색인 구현에서 나오며, 학습된 라우팅이나 어텐션과 같지 않다.

## 4. 시스템 번역 (Data Flow)

*이 개념을 하나의 살아있는 함수나 파이프라인으로 바라보고 해부해 봅니다.*

* **📥 인풋 (Input):** 검색 질의, 문서 컬렉션, 단어 빈도, 문맥 벡터, 모델 내부 토큰 표현
* **⚙️ 프로세스 (Processing):** 역색인이 질의어의 posting list에서 후보를 찾고, BM25가 질의·문서 통계로 관련도 점수를 계산한다. 일반적인 어텐션은 query·key·value와 마스크로 가중 결합 표현을 만든다.
* **📤 아웃풋 (Output):** BM25는 문서 점수와 랭킹을 내고, 어텐션은 다음 층으로 전달될 가중합 표현을 만든다.
* **💾 상태 (State):** BM25 점수 계산에는 문서 길이, 단어 빈도, 말뭉치 통계와 조정값이 필요하다. 검색 구현은 posting list를 관리하며, 어텐션은 표현·마스크·모델 파라미터와 실행 시 가중치를 구분한다.
* **🚨 터지는 조건 (Exception):** "0으로 걸러진다"는 결과만 보고 BM25를 어텐션이라고 부르거나, 모든 토큰을 보는 soft attention을 물리적 검색 라우팅으로 착각할 때 설명이 깨진다.

## 5. 핵심 구성요소 (Building Blocks)

* **레고 블록 1 (BM25):** 단어 빈도와 역문서 빈도를 이용해 문서 관련도를 계산하는 통계 기반 희소 검색 방식이다.
* **레고 블록 2 (Attention):** Query, Key, Value 사이의 벡터 유사도로 정보 흐름의 가중치를 정하는 신경망 메커니즘이다.
* **레고 블록 3 (SPLADE):** 언어 모델을 사용해 어휘 공간의 희소 표현을 학습하는 검색 접근이다. 모델 출력 변환, 희소화 목적과 학습 손실을 포함하며 BM25 수식을 학습하는 방식과 같지 않다.
* **서로 어떻게 맞물려 돌아가는가?:** BM25 점수 계산과 역색인 후보 검색은 분리된 단계다. SPLADE는 학습된 희소 표현을 검색에 사용하지만, 이를 어텐션이 BM25 벡터를 만드는 과정이라고 단순화하지 않는다.

## 6. 상태 전이 (State Transition)

*상태가 어떻게 변하는지 흐름을 한눈에 보여줍니다. (표 안의 문장은 짧고 직관적으로!)*

| 초기 상태 | 이벤트 (트리거) | 전이 조건 | 변경 후 상태 | "바뀐 걸 어떻게 알지?" (관찰 방법) |
| :--- | :--- | :--- | :--- | :--- |
| `RAW_QUERY` | 질의 토큰화 | 검색어가 단어 차원으로 분해됨 | `SPARSE_TERMS` | 질의에 남은 키워드 확인 |
| `SPARSE_TERMS` | 후보 검색 후 BM25 점수 계산 | 분석기·색인 설정과 문서 통계가 주어짐 | `RANKED_DOCS` | 문서 점수와 실제 랭킹 확인 |
| `TOKEN_EMBEDDINGS` | attention 계산 | Query-Key 유사도 산출 | `WEIGHTED_CONTEXT` | attention matrix 또는 가중합 확인 |
| `TOKEN_EMBEDDINGS` | SPLADE 계열 표현 생성 | 모델 출력 변환과 희소화 규칙 적용 | `LEARNED_SPARSE_VECTOR` | 비영 차원·가중치와 검색 지표 확인 |

어텐션은 항상 모든 토큰을 같은 방식으로 계산하지 않는다. 인과 마스크, 지역 어텐션, 희소 어텐션은 계산 범위를 제한할 수 있으며, 마스크와 수치 정밀도에 따라 가중치가 정확히 0이 될 수도 있다.

## 7. 불변식 (Invariant: 절대 깨지면 안 되는 규칙)

* **하늘이 무너져도 지켜야 할 조건:** BM25의 희소 라우팅 효과와 어텐션의 벡터 가중치 계산은 같은 결과처럼 보여도 같은 메커니즘이 아니다.
* **이게 깨지면 생기는 대참사:** 검색 시스템을 설계할 때 역색인으로 해결할 문제를 모델 내부 attention 문제로 오해하거나, 반대로 semantic context가 필요한 문제를 단순 키워드 점수로만 해결하려 든다.
* **수수방관 금지 (검증법):** 입력이 "단어가 있느냐"에 의해 걸러지는지, 아니면 "벡터 유사도와 학습된 가중치"로 정보가 흐르는지 처리 단계를 따라가며 확인한다.

## 8. 가장 작은 예제 (Minimal Viable Example)

* **뇌컴파일이 가능한 수준의 인풋:** 질의가 `사과 재배 병충해`이고 문서 A에는 `사과`, 문서 B에는 `배터리`, 문서 C에는 `사과 병충해`가 있다고 가정한다.
* **한 스텝씩 뜯어보기:** BM25는 역색인에서 `사과`, `재배`, `병충해`가 있는 문서 목록으로 바로 점프하고, 단어 빈도와 IDF로 A와 C의 점수를 계산한다. 어텐션은 문서 목록으로 점프하지 않고, 주어진 토큰 표현들 사이에서 어떤 토큰을 더 볼지 가중치를 계산한다.
* **해피 엔딩 (결과):** 이 예시는 후보 선택을 설명하는 사고 실험이다. A와 C의 순위는 문서 길이·빈도·말뭉치 통계와 조정값을 넣어 계산해야 하며, 어텐션 가중치도 실제 모델·입력·마스크 없이 확정할 수 없다.

| 항목 | BM25 | 일반적인 어텐션 |
| --- | --- | --- |
| 주된 목적 | 질의와 문서의 어휘 일치도 점수 계산 | 표현을 만들 때 다른 위치의 값을 가중 결합 |
| 입력 | 질의어 빈도, 문서어 빈도, 문서 길이, 말뭉치 통계 | query·key·value 표현과 마스크 |
| 학습 | 기본 수식 자체는 학습 파라미터가 없음; `k1`, `b` 등은 조정 가능 | 모델 파라미터와 함께 학습되는 경우가 일반적 |
| 0의 의미 | 질의어와 겹치는 색인 항목이 없으면 기여가 없을 수 있음 | 마스크, 수치 정밀도, 어텐션 방식에 따라 정확한 0 또는 작은 가중치 가능 |
| 실행 구조 | 보통 역색인의 posting list를 순회 | dense, masked, local, sparse 등 구현에 따라 다름 |

BM25를 “희소 벡터”로 표현할 수는 있지만 BM25 자체는 질의·문서 통계로 관련도 점수를 계산하는 랭킹 함수입니다. 역색인은 후보 문서를 효율적으로 찾는 자료구조이며 BM25 수식과 같은 개념이 아닙니다.

## 9. 실패 사례 (What could go wrong?)

* **폭망 시나리오 1:** BM25가 "중요 단어만 본다"는 이유로 어텐션 메커니즘을 쓴다고 설명한다.
* **폭망 시나리오 2:** 어텐션이 "중요 토큰에 집중한다"는 이유로 역색인처럼 물리적으로 검색 공간을 줄인다고 착각한다.
* **폭망 시나리오 3:** SPLADE를 보고 "BM25가 최신 모델에서는 어텐션으로 바뀌었다"고 단순화한다. 실제로는 언어 모델의 출력 변환과 희소화 학습을 거친 표현을 사용한다. 역색인 사용 여부와 BM25 점수 함수 사용 여부는 별개의 선택이다.
* **범인 검거 (어떤 불변식이 깨졌나?):** 효과의 유사성과 구현 메커니즘을 구분해야 한다는 7번 불변식이 깨졌다.

## 10. 뇌 확장하기 (Evolution & Variants)

* **조건을 살짝 바꾸면?:** 키워드가 정확히 맞는 검색에서는 BM25가 강하고, 문맥적 의미와 동의어 확장이 중요하면 dense retrieval이나 learned sparse retrieval이 필요해진다.
* **비슷한 놈들과 계급장 떼고 비교하기:** BM25는 전통적 sparse retrieval, dense vector search는 임베딩 기반 semantic retrieval, SPLADE는 neural sparse retrieval에 가깝다.
* **다른 데서 써먹기:** "겉보기 효과"와 "실제 메커니즘"을 분리하는 습관은 캐시, 라우팅, 추천, 모델 해석에서도 그대로 쓸 수 있다.

검색 방식의 비교에는 같은 말뭉치·분석기·후보 수에서 Recall@K, MRR 또는 nDCG, 색인 크기와 질의 지연을 기록한다. 어휘 일치, 의미 일반화, 지연과 색인 비용의 선택은 이 증거로 판단한다.
