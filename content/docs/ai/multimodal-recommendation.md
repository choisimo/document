# 다중 모달 추천 실험 설계

텍스트·이미지·영상 정보를 함께 사용하는 추천 시스템은 모달리티마다 입력 품질·비용·결측 처리가 다르다. 이 페이지는 보관 연구의 설계 주제를 복구한 것이며 구현된 서비스나 성능 보고서가 아니다.

## 먼저 고정할 계약

추천 대상, 허용된 입력 데이터, 사용자에게 보여 줄 결과, 지연 예산과 실패 시 기본 동작을 정한다. 클릭·시청·구매 같은 행동 데이터는 수집·보존 근거가 있어야 하며, 원본 미디어와 식별자를 공개 예시에 옮기지 않는다.

```text
허용된 입력
→ 모달리티별 전처리·특징 생성
→ 후보 생성
→ 순위화·정책 필터
→ 결과와 평가 기록
```

이는 일반적인 실험 단계다. 실제 내부 서비스 배치나 서버 연결도는 아니다.

## 비교할 선택지

| 부분 | 비교 질문 |
| --- | --- |
| 텍스트 | token 기반 기준선과 학습 임베딩이 어떤 오류에서 다른가? |
| 이미지 | 모델이 필요한 특징을 추출하는지, 입력 권한·크기·비용은 무엇인가? |
| 영상 | frame 선택·시간 정보·음성 처리가 목표에 필요한가? |
| 협업 신호 | 신규 사용자·신규 항목·희소한 이력에서 어떻게 동작하는가? |
| 결합·순위화 | 한 모달리티가 없을 때 결과와 confidence를 어떻게 처리하는가? |
| 캐시 | 모델·특징 버전이 바뀌면 무엇을 무효화해야 하는가? |

여러 모델을 결합하면 입력·배포·관측 복잡도가 늘어난다. 원문에 나열된 모델·라이브러리를 한꺼번에 필수 구성으로 지정하지 않는다. 단일 모달 기준선을 먼저 정하고 추가 신호가 어떤 품질 개선을 주는지 측정한다.

## 평가와 실패

학습·검증·평가 데이터 분리 기준과 시간 누출 여부를 기록한다. 추천 품질의 정의, 기준선, 하이퍼파라미터, 실행 하드웨어, 지연 분포와 반복 횟수가 있어야 수치를 비교할 수 있다.

유사한 항목만 반복 추천하는 현상, 신규 항목 누락, 특정 그룹에 대한 편향, 유해·권한 없는 결과, 오래된 캐시를 확인한다. embedding 점수가 높다는 이유만으로 관련성이나 사실성이 입증되지는 않는다.

실험 완료 기록에는 결과와 한계를 함께 남긴다. 구현되지 않은 분산 처리·캐시·추천 효과를 현재 기능으로 표시하지 않는다.
