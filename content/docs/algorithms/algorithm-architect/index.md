# Algorithm Architect Visual Docs 색인 학습 및 기록 노트

> 💡 **이 글을 쓰는 이유:** Algorithm Architect 문서 묶음은 그래프, 정렬, DP, 그리디, 트리, 비트마스크 같은 알고리즘 템플릿을 한곳에 모은 색인이다. 단순 링크 목록처럼 보여도, 학습자가 어떤 개념으로 바로 이동할지 결정하는 라우팅 문서 역할을 한다.

---

## 1. 왜 필요한가? (Pain Point & Motivation)

* **이 개념이 구원해 줄 문제:** 여러 알고리즘 문서가 흩어져 있을 때, 어떤 주제부터 열어야 하는지 빠르게 찾게 해 준다.
* **대안들의 한계 (기존의 똥떵어리들):** 파일 트리만 보고 찾으면 디렉터리 구조를 외워야 한다. 문서 묶음의 의도와 이동 경로가 없으면 관련 주제를 연결해서 학습하기 어렵다.

## 2. 현재 나의 상태 (Baseline)

* **여기까진 안다 (익숙한 땅):** 이 색인은 `algorithm-architect` 하위의 주요 알고리즘 문서로 이동하는 빠른 링크를 제공한다.
* **뇌정지 오는 부분 (안개 속):** 색인 문서도 단순 목록이 아니라 학습 흐름을 안내하는 문서라는 점을 놓치기 쉽다.
* **아직은 무리 (워너비):** 새 알고리즘 문서가 추가될 때 색인과 MkDocs nav가 함께 갱신되어야 한다.

## 3. 도달하고 싶은 목표 (Target State)

* **이 글을 끝내고 할 수 있는 일:** 알고리즘 템플릿 묶음에서 원하는 주제 문서로 바로 이동할 수 있다.
* **이것만은 건지자 (최소 성공 기준):** 그래프, 정렬/탐색, DP, 그리디, 트리, Union-Find, 투 포인터, 슬라이딩 윈도우, 백트래킹, 위상 정렬, 비트 마스킹 링크가 살아 있어야 한다.

## 4. 시스템 번역 (Data Flow)

*이 개념을 하나의 살아있는 함수나 파이프라인으로 바라보고 해부해 봅니다.*

* **📥 인풋 (Input):** 학습자가 찾는 알고리즘 주제, 문서 디렉터리 구조
* **⚙️ 프로세스 (Processing):** 주제를 카테고리별 링크로 매핑하고, 해당 Markdown 문서로 이동시킨다.
* **📤 아웃풋 (Output):** 선택한 알고리즘 학습 노트 문서
* **💾 상태 (State):** 색인 링크 목록, 실제 파일 경로, 문서 묶음 구성
* **🚨 터지는 조건 (Exception):** 링크 경로 불일치, 문서 추가 후 색인 누락, 이름과 실제 문서 내용 불일치

## 5. 핵심 구성요소 (Building Blocks)

* **레고 블록 1 (빠른 이동):** 전체 색인과 주요 카테고리 진입점을 제공한다.
* **레고 블록 2 (주제 링크):** 각 알고리즘 문서로 가는 상대 경로다.
* **레고 블록 3 (구성 원칙):** Mermaid, 핵심 코드, 상태 전이, 실전 체크리스트를 포함한다는 문서 작성 기준이다.
* **서로 어떻게 맞물려 돌아가는가?:** 빠른 이동이 학습자를 카테고리로 보내고, 주제 링크가 개별 학습 노트로 연결되며, 구성 원칙이 문서 형식을 일정하게 유지한다.

## 6. 상태 전이 (State Transition)

*상태가 어떻게 변하는지 흐름을 한눈에 보여줍니다. (표 안의 문장은 짧고 직관적으로!)*

| 초기 상태 | 이벤트 (트리거) | 전이 조건 | 변경 후 상태 | "바뀐 걸 어떻게 알지?" (관찰 방법) |
| :--- | :--- | :--- | :--- | :--- |
| `LANDING` | 색인 진입 | 알고리즘 묶음 열람 | `TOPIC_LISTED` | 주제 링크 목록 표시 |
| `TOPIC_LISTED` | 링크 선택 | 상대 경로가 존재함 | `DOC_OPENED` | 대상 문서로 이동 |
| `DOC_OPENED` | 학습 완료 | 다음 관련 주제 필요 | `BACK_TO_INDEX` | 색인으로 돌아와 다른 링크 선택 |

## 7. 불변식 (Invariant: 절대 깨지면 안 되는 규칙)

* **하늘이 무너져도 지켜야 할 조건:** 색인의 모든 내부 링크는 실제 존재하는 문서 파일을 가리켜야 한다.
* **이게 깨지면 생기는 대참사:** 학습 흐름이 끊기고, MkDocs 빌드나 링크 검증에서 실패한다.
* **수수방관 금지 (검증법):** 문서 추가/이동 후 링크 검증기를 실행하고, 색인 링크를 직접 열어 본다.

## 9. 실패 사례 (What could go wrong?)

* **폭망 시나리오 1:** 파일을 이동했는데 색인 링크를 갱신하지 않아 404가 난다.
* **폭망 시나리오 2:** 새 문서를 추가했지만 색인에 넣지 않아 찾을 수 없다.
* **폭망 시나리오 3:** 링크 이름과 실제 문서 내용이 달라 학습자가 잘못된 문서로 이동한다.
* **범인 검거 (어떤 불변식이 깨졌나?):** 모든 내부 링크가 실제 문서 파일을 가리켜야 한다는 7번 불변식이 깨졌다.

## 10. 뇌 확장하기 (Evolution & Variants)

* **조건을 살짝 바꾸면?:** 문서 수가 더 늘어나면 난이도, 문제 유형, 자료구조별 보조 색인을 추가할 수 있다.
* **비슷한 놈들과 계급장 떼고 비교하기:** README는 전체 상세 색인에 가깝고, `index.md`는 MkDocs에서 빠르게 진입하는 랜딩 문서에 가깝다.
* **다른 데서 써먹기:** CS 주제별 색인, 프로젝트 문서 허브, 운영 런북 카탈로그에도 같은 구조를 적용할 수 있다.

*복습 시 이 문장만 보고도 핵심을 떠올릴 수 있도록 빈칸을 채운다.*

> 이 개념은 결국 **알고리즘 문서 묶음에서 원하는 주제로 빠르게 이동하는 문제**를 해결하기 위해 태어났고,
> 우리가 계속 감시해야 할 핵심 상태는 **색인 링크와 실제 파일 경로의 대응** 이며,
