# 비트셋으로 부분집합 합 표현하기

비트셋 DP는 만들 수 있는 합을 비트 위치로 표현한다. 여기서는 음이 아닌 정수 무게를 각각 한 번 쓰는 **0/1 부분집합 합의 도달 가능성**만 다룬다. 가치 최대화 배낭이나 무제한 재사용 문제는 별도 점화식이 필요하다.

## 상태 갱신

bit k가 1이면 지금까지 처리한 항목으로 합 k를 만들 수 있다. 아무 항목도 선택하지 않은 합 0을 초기 상태로 켠다.

```cpp
#include <bitset>

std::bitset<8> possible;
possible.set(0);
possible |= possible << 2;
possible |= possible << 3;
// 켜진 위치: 0, 2, 3, 5
```

`possible << w`는 새 항목을 선택했을 때의 합이고 OR는 선택하지 않은 상태와 합친다. 오른쪽 식은 갱신 전 상태를 사용하므로 한 갱신에서 같은 항목을 반복 사용하지 않는다. 위 예시에서 무게 2를 하나만 넣었으므로 합 4는 켜지지 않는다.

## 범위와 실패 조건

`std::bitset<S>`가 표현하는 합은 0부터 S-1까지다. 그 밖으로 이동한 비트는 남지 않는다. 따라서 최대 합과 질의 범위를 먼저 정하고 bitset 크기를 선택한다. 표현 범위 밖의 합을 false라고 읽어 “수학적으로 불가능”하다고 결론 내리지 않는다.

음수 무게는 이 표현의 대상이 아니다. 0 무게는 reachability를 바꾸지 않는다. 중복 무게의 서로 다른 항목은 각 항목을 한 번씩 처리한다. 최대 합 계산의 정수 overflow와 질의 인덱스 범위도 확인한다.

## 성능과 검증

shift·OR는 여러 상태를 묶어 다루지만 항상 CPU 명령 하나나 일정한 배속을 보장하지 않는다. 저장 word 수, compiler, 라이브러리 구현과 목표 CPU에 따라 비용이 달라진다. 이 코드는 다중 thread 병렬 실행을 의미하지 않는다.

작은 입력의 모든 부분집합을 나열한 결과 또는 boolean DP와 비교한다. 합 0, 마지막 표현 가능 합, 범위 밖 합, 중복·0 무게를 포함하고 항목 처리 뒤 켜진 비트 집합을 확인한다. 실제 속도 비교에는 같은 입력·compiler 옵션·반복 횟수를 기록한다.
