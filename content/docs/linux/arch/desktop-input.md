# Linux 데스크톱 한글 표시·입력과 테마 진단

한글이 사각형으로 보이는 문제와 한영 전환이 안 되는 문제는 다를 수 있다. 로캘·글꼴·입력기·앱 통합을 한 번에 바꾸지 말고 실제 데스크톱과 세션 종류를 먼저 기록한다.

| 증상 | 먼저 확인 |
| --- | --- |
| 문자 깨짐·사각형 | 로캘, 파일 인코딩, 선택 글꼴의 한글 glyph |
| 읽기는 되지만 입력이 안 됨 | 선택 입력기, 실행 상태, 입력 소스·전환 키 |
| 특정 앱에서만 실패 | 그 앱의 toolkit·세션·입력기 통합 |
| 재로그인하면 설정 소실 | 세션이 실제로 읽는 환경·자동 시작 경로 |
| 테마 변경 후 화면 불안정 | 기본 테마에서 재현 여부, extension 호환성 |

## 읽기 전용 진단부터

```bash
locale
locale -a
fc-match sans-serif
```

로캘을 생성하는 작업과 기본 UI 언어를 고르는 작업은 다르다. 영어 UI에서도 한글 표시·입력을 사용할 수 있다. 글꼴 선택 결과와 실제 앱에서의 표시를 함께 확인한다.

## 입력기 선택

보관 자료에는 IBus와 Fcitx5 경로가 있다. 두 경로의 환경 변수와 자동 실행을 무조건 함께 적용하지 않는다. desktop이 관리하는 입력기 실행 방식과 충돌할 수 있다.

특히 X11 예시의 전역 `GTK_IM_MODULE`, `QT_IM_MODULE`, `XMODIFIERS`를 모든 Wayland 세션에 그대로 적용하지 않는다. compositor·toolkit·앱별 통합이 다르므로 선택한 입력기의 해당 환경 안내를 확인한다.

환경 변경 뒤에는 새 로그인 세션에서 일반 편집기와 문제가 있던 앱을 각각 시험한다. 전환 키, 한글 조합, 확정·삭제, 터미널과 브라우저 입력을 확인한다. 명령이 성공했다는 사실보다 실제 입력 결과가 완료 증거다.

## GNOME·KDE 테마 변경

GNOME shell·앱 테마·아이콘·글꼴·extension은 서로 다른 범위다. 패키지나 extension의 지원 버전이 확인되지 않은 보관 명령을 최신 설치법으로 복사하지 않는다. 기본 테마에서 시작해 한 요소씩 변경하고 읽기 대비·포커스·입력창·로그인 화면을 확인한다.

현재 KDE 자료는 [테마와 설정 관리](kde-theme.md)에 있다. GUI에 들어갈 수 없는 경우를 대비해 TTY 로그인과 설정 복구 사본을 유지한다. 문제 발생 시 관련 변경만 되돌리고 사용자 설정 전체를 지우는 절차는 피한다.
