# 문서 기여와 보관 자료 복구

새 문서는 독자가 해야 할 일과 현재 빠진 설명을 먼저 정한다. 파일 수를 늘리기 위해 보관본 전체를 복사하지 않는다. 실행 방법·개념 설명·설계 제안·장애 기록은 서로 다른 문서 종류다.

## 1. 원본과 기존 문서 확인

저장소 루트에서 주제와 파일을 찾는다.

```bash
rg --files content/docs -g '*.md'
rg -n '찾을 주제' content/docs -g '*.md'
rg --files --hidden --no-ignore content/archive content/prompts content/research -g '*.md' -g '*.txt'
```

보관 경로 일부는 `.gitignore`에 있으므로 기본 검색만으로 전체를 조사했다고 말할 수 없다. 검색 결과의 원문을 읽고 현재 공개 페이지와 의미를 비교한다. 제목이 같아도 내용이 다를 수 있고, 이름이 달라도 이미 같은 계약을 설명할 수 있다.

| 판정 | 처리 |
| --- | --- |
| 현재 공개 문서가 필요한 내용을 설명 | 해당 정본으로 연결하고 반복본을 만들지 않음 |
| 기존 공개 문서에 없는 독립 주제 | 민감한 내용을 제거한 새 문서 작성 |
| 당시 환경에만 맞는 설치 명령·진단 결론 | 환경·버전 확인 전에는 현재 절차로 승격하지 않음 |
| 개인 메모·배포 자격증명·운영 주소·팀 기록 | 본문과 예시에서 제외 |
| 생성 HTML·PDF·스크린샷·보고서 | 생성물 자체를 정본으로 편집하지 않음 |

## 2. 문서 작성

파일은 `content/docs/<topic>/` 아래에 둔다. 명령의 작업 디렉터리, 입력, 결과물, 실패 시 중단 조건을 적는다. 소스에서 보인 설정과 실제 실행 결과를 구분한다. 실행하지 않았다면 “실행 검증 전 예시”라고 명시한다.

```yaml
---
title: 읽는 사람이 수행할 작업
description: 이 문서가 해결하는 문제와 적용 범위를 한 문장으로 설명합니다.
tags:
  - documentation
intent: howto
---
```

현재 hook의 `intent` 값은 `howto`, `reference`, `comparison`, `troubleshooting`이다. 생략하면 제목·경로로 추정한다. `date`는 실제 확인한 날짜가 있을 때만 적는다. 근거 없는 최신성·성능 수치·완료 표시를 만들지 않는다.

새 예시는 `example.com`, `com.example`, `<SERVICE>` 등 공개 예시용 값을 쓴다. 계정 이름, 내부 도메인, 주소, 키, 실제 데이터, 전체 내부 연결도를 복원할 수 있는 조합은 옮기지 않는다. 외부 글의 HTML 보관본은 재배포 권한을 확인해야 하며, 원문 복사 대신 필요한 개념을 독립적으로 설명한다.

## 3. 탐색과 링크 연결

`apps/docs-site/mkdocs.yml`의 기존 주제 아래에 추가하고, 새 문서군이면 색인도 작성한다. 문서 간 링크는 `.md` 상대 경로를 우선한다. 저장소 소스 경로는 코드 표기로 적어 출처와 웹 URL을 구분한다.

경로를 바꾸면 nav, 기존 문서 링크, 외부 공유 URL, 문서 ID 변경 영향을 확인한다. `MIGRATION_MAP.md`는 과거 이동 대응표이며 지금도 모든 원본이 존재하거나 공개에 적합하다는 증거가 아니다.

## 4. 완료 기록

[개발 환경 안내](local-development.md)의 검사로 본문·링크·탐색을 확인한다. 리뷰 기록에는 변경 경로, 읽은 소스와 symbol 또는 줄, 실행한 명령·종료 코드, 검증하지 못한 외부 동작을 남긴다. 문법 검사가 통과해도 사실성이나 비밀정보 부재까지 자동으로 입증되지는 않는다.
