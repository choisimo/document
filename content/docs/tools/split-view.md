# Split View

Split View는 문서 사이트 안에서 여러 문서를 동시에 열어 비교하는 화면 분할 기능이다. 구현은 `content/docs/javascripts/split-view.js`에 있으며, 최대 2x2 패널과 세션별 검색, 히스토리, 상태 복원을 제공한다.

## 1. 왜 필요한가? (Pain Point & Motivation)

기술 문서를 읽을 때는 한 문서만 보는 경우보다 비교하면서 읽는 경우가 많다. 예를 들어 설치 가이드, 명령어 레퍼런스, 문제 해결 문서, 관련 개념 문서를 오가면 브라우저 탭이 빠르게 늘어난다.

Split View의 목적은 문서 탐색을 한 화면 안으로 모으는 것이다. 각 패널이 독립 세션처럼 동작하므로, 한쪽에는 현재 문서를 고정하고 다른 쪽에서는 검색 결과를 열어 비교할 수 있다.

## 2. 현재 나의 상태 (Baseline)

다음 상태라면 Split View가 유용하다.

- 여러 문서를 번갈아 보느라 브라우저 뒤로 가기와 탭 이동이 많다.
- 설정 예제와 설명 문서를 동시에 보고 싶다.
- 검색 결과를 열 때마다 현재 읽던 위치를 잃는다.
- Mermaid 다이어그램, 표, 코드 블록이 포함된 문서를 비교해야 한다.
- 한 문서의 링크를 같은 패널 안에서 계속 따라가고 싶다.

## 3. 도달하고 싶은 목표 (Target State)

Split View를 제대로 사용하면 다음 상태가 된다.

- 현재 페이지를 활성 패널에 바로 불러올 수 있다.
- 패널마다 검색어, 현재 문서, 히스토리가 분리된다.
- `1x1`, `1x2`, `2x1`, `2x2` 레이아웃을 전환할 수 있다.
- 패널 크기와 레이아웃은 브라우저 로컬 저장소에 저장된다.
- 내부 링크는 전체 페이지 이동이 아니라 같은 패널 안에서 로드된다.
- 작은 화면에서는 모바일 레이아웃이 우선 적용된다.

## 4. 시스템 번역 (Data Flow)

문서 로딩 흐름은 다음과 같다.

```text
사용자 입력
  -> 패널 선택
  -> 검색어 입력 또는 현재 페이지 로드
  -> 검색 인덱스 조회
  -> 문서 URL 선택
  -> HTML fetch
  -> 본문 추출
  -> 패널 내부 렌더링
  -> 세션 히스토리 저장
```

검색은 `MkDocs.SEARCH_INDEX_URL`과 `DocSearchEngine`을 사용한다. 문서를 열 때는 페이지 전체를 iframe으로 넣는 방식이 아니라 HTML을 가져와 본문 영역을 추출한 뒤 패널 내부에 삽입한다.

## 5. 핵심 구성요소 (Building Blocks)

- Toggle button: Split View를 여닫는 버튼이다.
- Container: 전체 분할 화면을 담는 오버레이다.
- Toolbar: 현재 페이지 로드, 레이아웃 선택, 닫기 버튼을 제공한다.
- Layout selector: `1x1`, `1x2`, `2x1`, `2x2` 중 하나를 선택한다.
- Pane: 하나의 독립 문서 세션이다.
- Session: 현재 URL, 제목, 검색어, 검색 결과, 스크롤 위치, 히스토리를 가진다.
- Search index: 문서 검색에 사용하는 MkDocs 검색 데이터다.
- Content pipeline: URL 정규화, HTML fetch, 본문 추출, 정리, Mermaid와 코드 블록 후처리를 수행한다.
- Local storage: `splitview-state` 키로 레이아웃과 세션 상태를 저장한다.

## 6. 상태 전이 (State Transition)

Split View의 큰 상태 흐름은 다음과 같다.

```text
closed
  -> open
  -> session_selected
  -> searching
  -> document_loaded
  -> closed
```

패널 하나의 상태는 다음처럼 움직인다.

```text
empty
  -> search_results
  -> loading
  -> document_loaded
  -> error
```

- `empty`: 아직 문서가 열리지 않은 패널이다.
- `search_results`: 검색 결과 목록이 표시된다.
- `loading`: 선택한 문서를 가져오는 중이다.
- `document_loaded`: 본문이 패널 안에 렌더링됐다.
- `error`: 검색 인덱스나 문서 fetch가 실패했다.

검색 중 새 요청이 들어오면 세션별 요청 번호로 오래된 결과를 무시한다. 문서 로딩 중 새 문서를 열면 이전 fetch는 `AbortController`로 취소된다.

## 7. 불변식 (Invariant: 절대 깨지면 안 되는 규칙)

- 활성 패널은 항상 하나만 있어야 한다.
- 패널 내부 링크 클릭은 전체 페이지를 이동시키지 않고 해당 패널 안에서 처리해야 한다.
- 검색 결과가 늦게 도착해도 더 최신 검색 결과를 덮어쓰면 안 된다.
- 이전 문서 로딩 요청은 새 요청이 시작되면 취소해야 한다.
- 저장된 localStorage 상태가 깨져도 Split View 자체는 열려야 한다.
- 모바일 폭에서는 저장된 2x2보다 모바일 레이아웃이 우선되어야 한다.
- 본문 삽입 시 `script`, footer 같은 외부 페이지 크롬은 제거해야 한다.
- Mermaid와 코드 복사 버튼 같은 후처리는 패널 안에서 다시 적용되어야 한다.

## 8. 가장 작은 예제 (Minimal Viable Example)

기본 사용 흐름은 다음과 같다.

```text
1. Ctrl+\ 로 Split View를 연다.
2. 첫 번째 패널에서 "현재 보고 있는 페이지 로드"를 누른다.
3. 두 번째 패널을 클릭한다.
4. Ctrl+/ 로 검색창에 포커스한다.
5. 검색어를 입력하고 결과를 클릭한다.
6. Ctrl+Arrow로 패널을 이동하며 비교한다.
```

주요 단축키는 다음과 같다.

| 단축키 | 동작 |
| --- | --- |
| `Ctrl+\` | Split View 열기 또는 닫기 |
| `Esc` | Split View 닫기 |
| `Ctrl+/` | 활성 패널 검색창 포커스 |
| `Alt+Left` | 활성 패널 뒤로 가기 |
| `Alt+Right` | 활성 패널 앞으로 가기 |
| `Ctrl+Arrow` | 패널 간 이동 |
| `Ctrl+Shift+1` ~ `Ctrl+Shift+4` | 세션 직접 선택 |
| `Ctrl+Shift+C` | 현재 페이지를 활성 패널에 로드 |

레이아웃은 다음 네 가지다.

| 레이아웃 | 의미 |
| --- | --- |
| `1x1` | 단일 패널 |
| `1x2` | 1행 2열 |
| `2x1` | 2행 1열 |
| `2x2` | 2행 2열 |

## 9. 실패 사례 (What could go wrong?)

- 검색 인덱스를 불러오지 못해 패널 검색이 실패한다.
- 문서 fetch가 실패해 패널에 오류가 표시된다.
- 깨진 localStorage 상태가 남아 레이아웃 복원이 실패한다.
- 내부 링크 처리에 빠진 링크가 전체 페이지를 이동시킨다.
- 패널 안의 Mermaid 다이어그램이 라이브러리 로딩 순서 문제로 렌더링되지 않는다.
- 너무 작은 화면에서 2x2를 강제하면 패널 내용이 읽기 어렵다.
- 긴 표나 코드 블록이 패널 폭을 넘어 스크롤 처리가 필요하다.

## 10. 뇌 확장하기 (Evolution & Variants)

Split View는 문서 탐색 기능이므로 다음 방향으로 확장할 수 있다.

- 패널별 북마크 또는 고정 기능 추가.
- 패널 간 URL 복사와 이동 기능 추가.
- 검색 결과에서 현재 열린 문서와 관련된 문서를 우선 정렬.
- 세션 상태를 localStorage가 아니라 URL 쿼리로 공유.
- 모바일에서 1x1 탭 방식으로 세션 전환.
- 테스트 시 Playwright로 단축키, 검색, 패널 내부 링크, 상태 복원을 검증.

확장할 때도 핵심은 패널 간 상태 격리다. 한 패널의 검색, 히스토리, 로딩 실패가 다른 패널의 문서를 덮어쓰면 안 된다.

## 11. 최종 체크리스트 (Definition of Done)

- [ ] `Ctrl+\`로 열고 닫히는지 확인했다.
- [ ] `1x1`, `1x2`, `2x1`, `2x2` 레이아웃이 전환된다.
- [ ] `Ctrl+/`가 활성 패널의 검색창에 포커스한다.
- [ ] 검색 결과 클릭 시 문서가 같은 패널 안에 열린다.
- [ ] 내부 링크 클릭이 전체 페이지 이동을 만들지 않는다.
- [ ] `Alt+Left`, `Alt+Right` 히스토리 이동이 동작한다.
- [ ] 새 문서 로딩 중 이전 요청이 취소된다.
- [ ] 새로고침 후 저장된 상태가 복원된다.
- [ ] 모바일 폭에서는 읽을 수 있는 레이아웃으로 전환된다.

## 12. 뇌에 새기는 복습 문장 (TL;DR Blank)

Split View의 핵심은 여러 문서를 한 화면에 띄우는 것이 아니라, 각 패널의 `____`, `____`, `____`를 서로 섞이지 않게 유지하는 것이다.
