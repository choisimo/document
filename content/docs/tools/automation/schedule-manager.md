# 비개발자용 오픈소스 일정 관리 도구 비교 보고서

이 보고서는 Docker로 자체 호스팅할 수 있는 일정 및 예약 도구의 용도와 운영 부담을 비교합니다. 검증 가능한 출처가 없던 사용자 수, 만족도, 처리량, 메모리와 설문 수치는 의사결정 근거에서 제외했습니다.

## 조사 범위와 판정 방법

후보의 이름만으로 추천 순위를 정하지 않습니다. 평가일에 공식 저장소와 릴리스 노트에서 유지보수 상태, 라이선스, 지원 데이터베이스, 인증 기능, 백업과 업그레이드 절차를 확인하고 작은 시험 환경에서 실제 업무 흐름을 검증합니다.

| 기준 | 확인할 증거 |
|---|---|
| 업무 적합성 | 개인 캘린더, 고객 예약, 자원 예약, 프로젝트 일정 중 필요한 흐름의 시연 |
| 유지보수성 | 최근 릴리스, 보안 공지, migration 문서, 지원 버전과 복구 절차 |
| 사용자 경험 | 실제 사용자 대상 모바일 및 접근성 과업 시험 |
| 통합 | CalDAV, Google/Microsoft 연동, SSO, webhook의 실제 성공 및 실패 로그 |
| 운영 비용 | 측정한 CPU, 메모리, 저장소, 백업 시간과 외부 API 비용 |
| 보안 | 기본 계정, MFA/SSO, 역할, 감사 로그, secret 관리와 공개 취약점 대응 |

## 후보별 적합성

### 1. Easy!Appointments

고객이 시간대를 선택하는 약속 예약이 핵심일 때 검토합니다. 서비스 제공자, 휴일, timezone, 중복 예약과 외부 캘린더 동기화가 실제 요구를 충족하는지 시험합니다. 공식 배포 경로와 지원 DB 버전을 확인하고 검토한 이미지 digest를 고정합니다.

### 2. Booked Scheduler 계열

회의실, 장비와 같은 자원 예약 흐름에 적합할 수 있습니다. 원 프로젝트와 fork, 제3자 Docker 이미지의 유지보수 주체를 구분해야 합니다. PHP 및 DB 지원 버전, 플러그인 호환성과 보안 패치 주기를 충족하지 못하면 후보에서 제외합니다.

### 3. Cal.com

외부 예약 페이지와 화상회의 통합이 필요한 조직에서 검토합니다. self-hosted 기능과 라이선스 경계, 필수 환경 변수, PostgreSQL migration, 이메일과 OAuth redirect URL을 현재 릴리스 기준으로 확인합니다. 동시 사용자 수와 캐시 크기는 고정 수치가 아니라 대표 시나리오 부하 시험으로 산정합니다.

### 4. Plane

Plane은 프로젝트 및 이슈 관리가 중심이므로 단순 예약 도구와 같은 범주로 점수화하지 않습니다. 프로젝트 캘린더와 개발 워크플로우가 주 요구일 때만 후보로 두고, 서비스 수가 많은 배포의 백업 순서와 upgrade runbook까지 운영 비용에 포함합니다.

### 5. Radicale 또는 Baikal

CalDAV/CardDAV 중심의 경량 동기화가 필요할 때 각각을 독립 후보로 평가합니다. 두 제품을 임의로 결합한 구성을 하나의 지원 제품처럼 가정하지 않습니다. 클라이언트 호환성, 사용자 관리, TLS reverse proxy, 저장소 권한과 데이터 복원을 시험합니다.

## 안전한 Docker 평가 절차

latest 태그, 예제 root 비밀번호와 출처가 불명확한 이미지는 사용하지 않습니다.

1. 공식 저장소에서 지원 설치 경로와 검토할 release를 선택합니다.
2. 이미지 tag와 digest, Compose 파일, migration 및 최소 자원 요구를 기록합니다.
3. 비밀은 저장소 밖에서 주입하고 관리 UI는 loopback 또는 격리된 시험망에만 노출합니다.
4. 샘플 데이터를 만든 뒤 예약 생성, 변경, 취소, 충돌, timezone과 알림 실패를 시험합니다.
5. DB와 첨부 데이터를 백업하고 빈 환경에 복원합니다.
6. 한 버전 업그레이드와 실패 시 이전 버전 복구를 수행해 소요 시간과 데이터 손실 여부를 기록합니다.

## 실패와 재시도

메일, webhook과 외부 캘린더 동기화는 timeout, rate limit, 중복 이벤트와 부분 성공을 구분해야 합니다. 쓰기 재시도에는 idempotency 또는 중복 억제 기준을 두고, queue 적체와 dead-letter 상태를 관측합니다. migration 실패 후 새 컨테이너를 반복 실행하지 말고 DB 백업과 로그를 보존해 롤백합니다.

## 선택 결론

보편적인 1위는 없습니다. 고객 예약은 Easy!Appointments와 Cal.com, 자원 예약은 유지보수되는 Booked 계열, 프로젝트 일정은 Plane, 표준 캘린더 동기화는 Radicale 또는 Baikal을 각각 짧은 목록으로 둘 수 있습니다. 최종 선택은 위 증거표와 실제 사용자 과업 시험을 통과한 후보 중에서 운영 역량과 총비용을 포함해 결정합니다.

## 완료 조건

선택 보고서에는 평가일, 정확한 버전과 라이선스, 제외 사유, 기능 시험 결과, 측정 자원, 보안 검토, 백업 복원과 upgrade 또는 rollback 증거, 남은 위험과 담당자를 포함합니다.
