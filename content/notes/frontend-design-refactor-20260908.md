## 화면별 책임

- 홈: 기존 Material 검색을 열고, 여섯 주제 목록과 Compose·CS 자료실 바로가기를 제공한다.
- CS 자료실: 26개 주제의 한국어·영어 문서를 언어, 분류, 검색어로 찾는다. 결과 없음 안내와 초기화를 제공하고 JavaScript 없이도 문서 링크를 읽을 수 있게 한다.
- 공통 화면: 일곱 상단 메뉴 그룹, 명확한 활성 메뉴, 읽기 폭과 본문 타이포그래피, 모바일에서 제목과 겹치지 않는 문서 도구를 담당한다.
- 분류 인덱스: 27개 페이지의 문서·정적 자료 링크를 설명보다 앞에 배치한다. 현재 학습 본문과 다이어그램은 펼쳐진 안내 영역에 유지한다.
- 학습 노트: 기존 홈과 CS 인덱스의 긴 기록은 각각 [홈 유지보수 노트](documentation-hub-maintenance.md), [CS 학습 경로 노트](cs-reference-learning-paths.md)에 보존한다.

기존 Material 테마, 색상 토큰, 검색과 페이지 전환을 사용한다. 새 프레임워크나 원격 글꼴을 추가하지 않는다. 홈·자료실의 넓은 탐색 레이아웃과 일반 문서의 읽기 레이아웃을 분리한다. 기존 문서 경로는 유지한다.

## 변경 시 확인할 항목

소스 파일의 존재 확인에 더해 MkDocs strict 빌드 결과의 링크와 앵커를 검사한다. 브라우저에서는 검색 결과, 필터 조합과 초기화, 키보드 조작, 즉시 페이지 전환 후 재초기화, JavaScript 비활성 상태, 밝은·어두운 테마와 좁은 화면을 확인한다.

```sh
python -m mkdocs build --strict -f apps/docs-site/mkdocs.yml
bash src/automation/site/sync-extra-assets.sh
HOME_SITE_DIR="$PWD/dist/site" \
CATALOG_SITE_DIR="$PWD/dist/site" \
DIRECTORY_SITE_DIR="$PWD/dist/site" \
SHELL_SITE_DIR="$PWD/dist/site" \
npm --prefix src run qa:test
```

스크린샷만으로 기능 검증을 대신하거나, 소스 검사 통과를 실제 렌더링 성공으로 간주하지 않는다.

Pages 빌드 워크플로도 정적 자산 복사 후 이 브라우저 검사를 실행한다. 홈 마크업·자료실 필터가 없어지거나 실제 탐색이 실패하면 배포 단계 전에 실패한다.

홈 검색은 즉시 페이지 전환 직후 Material의 지연 정리와 충돌하지 않도록 초기화가 끝난 후 활성화한다. 실제 키 입력, 현재 검색어의 보이는 결과, 페이지 전체 재로드 없이 왕복한 상태를 확인했다. 모바일 메뉴는 닫힌 패널과 뒤에 가려진 부모 항목이 포커스를 받지 않으며, 하위 메뉴·뒤로 이동·검색·분할 보기 사이의 키보드 전환을 검사했다.

복원한 링크는 `--link-root dist/site`로 실제 생성 파일도 확인한다. 원본 문서가 있으면 그 파일과 앵커를 우선 검사하며, 생성 파일을 근거로 원본 오류를 무시하지 않는다. `--link-root`를 생략한 기존 소스 전용 검사는 생성 전용 링크를 계속 실패로 보고한다.

전체 생성 HTML 검사에서는 새 누락 링크가 없었다. 기존 raw 시뮬레이터 두 사본의 누락 자산 8개와 보관 HTML의 누락 참조 73개는 별도 잔여 항목이다. GitHub 저장소 통계 API의 403 응답도 별도로 관찰했으며, 최종 화면 캡처는 반복 API 요청을 차단했다. 외부 서비스 응답이나 전체 책의 Mermaid 브라우저 렌더링까지 완료한 결과로 해석하지 않는다.
