# 운영체제 개념 및 실습 문제

> **학습 범위:** 이 문서는 운영체제의 목적, 펌웨어와 저장장치의 역할, `fork()` 기반 프로세스 생성, IPC, 커널 구조를 서술형·설계형 문제로 점검합니다. 정답은 용어 정의만이 아니라 전제, 상태 변화, 실패 조건을 포함해야 합니다.

운영체제는 하드웨어 자원을 중재하고 프로그램에 실행·저장·통신 추상화를 제공합니다. 아래 문제는 자원 관리, 격리, 동시 실행이라는 세 관점에서 설명할 수 있는지를 평가합니다.

## 운영체제 사용 목적 힌트

### 힌트 1: 자원 관리

컴퓨터에는 CPU, 메모리, 저장장치, 입출력 장치 등 다양한 하드웨어 자원이 있다. 여러 프로그램이 동시에 실행될 때 운영체제는 이러한 자원을 분배하고 관리한다.[1][3]

### 힌트 2: 인터페이스

사용자가 하드웨어를 직접 제어하려면 전기 신호와 기계어를 이해해야 한다. 운영체제는 시스템 콜, 파일, 프로세스, 네트워크 인터페이스로 이러한 복잡성을 추상화한다.[2][6]

### 힌트 3: 다중 작업

웹 브라우저, 음악 재생, 문서 편집을 동시에 실행할 수 있는 이유는 프로세스와 스레드 관리, CPU 스케줄링, 메모리 보호, 입출력 관리 때문이다.[1][5]

### 힌트 4: 추상화

프로그래머는 하드웨어 세부 사항을 직접 다루지 않고 파일 저장, 네트워크 통신, 프로세스 생성 같은 작업을 수행한다. 운영체제는 이러한 기능을 추상화된 API로 제공한다.[6]

### 힌트 5: 보안

여러 사용자와 프로그램이 같은 컴퓨터를 사용할 때 운영체제는 권한, 주소 공간 분리, 파일 접근 제어, 프로세스 격리로 데이터와 작업을 보호한다.[5]

## Firmware와 Disk의 차이점 문제

### 문제 1: 시스템 부팅 과정 분석

컴퓨터 전원 인가 후 BIOS/UEFI가 먼저 실행되고, 그 후 운영체제가 로드된다. 이 과정에서 firmware와 disk가 각각 어떤 역할을 하는지 설명하고, firmware 손상과 disk 손상이 시스템에 미치는 영향 차이를 분석한다.

### 문제 2: 업데이트 실패 영역 비교
펌웨어 플래시 갱신과 디스크의 운영체제 파일 갱신 중 전원이 꺼졌다고 가정합니다. 각 작업에서 원자성이 보장되는 단위, 부팅 가능성, 복구 매체와 롤백 경로가 어떻게 다른지 설명하세요. 단순히 “비휘발성이므로 안전하다”고 결론 내리지 말고 갱신 중인 구성요소를 식별하세요.

### 문제 3: 접근 메커니즘 설계

중요한 보안 설정을 firmware에 저장할지 disk에 저장할지 결정할 때, 접근 속도, 수정 용이성, 보안성 측면에서 고려할 요소를 분석한다.

## `fork()` 호출 순서와 호출 개수 문제

> **코드 상태:** 아래 예제에는 `fork()`, `getpid()`, `wait()`에 필요한 헤더가 포함되어 있다. 프로세스 수와 출력 예측은 모든 `fork()`가 성공한다는 가정하에 수행한다. 실행 실습에서는 각 `fork()`의 실패 반환과 `wait()` 결과를 처리하고, 출력 순서가 스케줄링에 따라 달라질 수 있음을 확인한다.

### 문제 1: 프로세스 생성 계산

다음 코드를 실행했을 때 생성되는 총 프로세스 수, 원래 프로세스 포함 개수를 계산한다.[1][3]

```c
#include <stdio.h>
#include <unistd.h>

int main() {
    fork();
    fork();
    fork();
    printf("Hello\n");
    return 0;
}
```

### 문제 2: 출력 예측

다음 코드를 실행했을 때 `"Process ID"`가 몇 번 출력되는지 예측하고, 각 출력에서 `pid` 값의 관계를 설명한다.[1][3]

```c
#include <stdio.h>
#include <unistd.h>

int main() {
    pid_t pid;

    pid = fork();
    if (pid == 0) {
        fork();
        printf("Process ID: %d\n", getpid());
    } else {
        fork();
        printf("Process ID: %d\n", getpid());
    }

    return 0;
}
```

### 문제 3: 조건부 `fork()` 분석

다음 코드에서 변수 `x`의 최종값이 가능한 모든 경우를 나열하고, 각 프로세스의 실행 흐름을 설명한다.[3]

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main() {
    int x = 1;
    pid_t pid;

    pid = fork();
    if (pid == 0) {
        x += 5;
        printf("Child: x = %d\n", x);
    } else {
        wait(NULL);
        x += 10;
        printf("Parent: x = %d\n", x);
    }

    return 0;
}
```

## 자식 프로세스 구성 문제

### 문제 1: 프로세스 트리 설계

프로세스 A가 두 개의 자식 프로세스 B와 C를 생성한다. 프로세스 B는 자식 프로세스 D를 생성하고, 프로세스 C는 자식 프로세스 E와 F를 생성한다. 이 프로세스 트리를 만드는 코드를 작성한다.[3][4]

### 문제 2: IPC를 활용한 협력 프로세스

부모 프로세스가 `n`개의 자식 프로세스를 생성하고, 각 자식 프로세스는 1부터 10까지의 숫자 중 하나를 무작위로 생성한다. 자식 프로세스들은 `pipe`를 통해 이 숫자를 부모 프로세스에게 전송하고, 부모 프로세스는 모든 숫자의 평균을 계산하여 출력한다. 이 시나리오를 구현하는 코드를 작성한다.[3][4]

### 문제 3: 프로세스 동기화

세 개의 프로세스 A, B, C가 `A -> B -> C -> A -> B -> C -> ...` 순서로 반복 실행된다. 이 순환적 실행 순서를 보장하기 위해 공유 메모리와 세마포어를 사용하는 코드를 설계한다. 각 프로세스는 실행될 때마다 자신의 ID를 출력한다.[3][4]

## 운영체제 설계 문제

### 문제 1: 마이크로커널 vs 모놀리식 커널

리눅스와 같은 모놀리식 커널과 Mach와 같은 마이크로커널의 핵심 설계 철학 차이를 설명하고, 각 접근 방식의 장단점을 성능, 안정성, 확장성 측면에서 분석한다.[5]

### 문제 2: 가상 메모리 설계

페이지 교체 알고리즘(LRU, FIFO, 최적 알고리즘)의 성능을 다양한 워크로드에서 비교하는 시뮬레이션을 설계한다. 알고리즘별로 효율적인 상황과 그 이유를 분석한다.[1]

### 문제 3: 시스템 콜 최적화
리눅스 커널에서 프로세스 생성과 관련된 시스템 콜(`fork`, `clone`)의 비용을 측정할 워크로드와 지표를 먼저 정의한 뒤 개선안을 제안하세요. Copy-on-Write 변경안은 페이지 테이블 복사, 첫 쓰기 지연, 메모리 사용량 중 어떤 비용을 줄이는지 밝히고, 정확성·격리·회귀 검증 기준을 함께 설명하세요.[3]
