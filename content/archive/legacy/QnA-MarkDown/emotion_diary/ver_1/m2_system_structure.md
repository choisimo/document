### 2.2 컴포넌트별 역할

#### 2.2.1 Frontend (사용자 인터페이스)

- 사용자 등록 및 로그인 인터페이스
- 일기 작성 및 조회 화면
- 감정 분석 결과 시각화 대시보드
- 추천 컨텐츠 및 알림 표시


#### 2.2.2 Backend (서버 및 비즈니스 로직)

- 사용자 인증 및 권한 관리
- API 엔드포인트 제공
- 데이터 처리 및 비즈니스 로직 수행
- AI 모듈과의 통신 및 결과 처리


#### 2.2.3 AI Module (감정 분석 엔진)

- 텍스트 전처리 및 감정 분석
- ChatGPT API 연동
- 감정 패턴 인식 알고리즘
- 맞춤형 추천 생성

#### 2.2.3-1 AI Module (인지 행동 치료)
- 부정적 감정일 시에만 작동하는 모듈
- 인지 행동 프롬프트


#### 2.2.4 Database (데이터 저장소)

- 사용자 정보 저장
- 일기 데이터 관리
- 감정 분석 결과 저장
- 추천 및 피드백 데이터 관리
- 외부 AI API가 요청 간 상태를 보존하지 않는다는 가정하에 대화·분석 이력의 기준 데이터는 Database에 저장
- Redis에는 재생성 가능한 조회 결과만 만료 시간과 함께 캐시하고, 캐시 손실을 사용자 데이터 손실로 처리하지 않음

### 2.3 컴포넌트 경계와 실패 상태

| 경계 | 허용되는 입력·출력 | 실패 시 상태 |
| --- | --- | --- |
| Frontend → Backend | 인증 정보와 길이·형식 검사를 통과한 일기 작성/조회 요청 | 사용자에게 재시도 가능 여부를 구분해 표시 |
| Backend → AI Module | 분석 식별자와 최소화된 텍스트, 버전이 고정된 출력 스키마 | 원문은 보존하고 분석 상태를 `failed` 또는 `retry_pending`으로 기록 |
| AI Module → Backend | 감정 레이블, 점수, 모델/프롬프트 버전, 안전 필터 결과 | 스키마 불일치 결과는 저장·노출하지 않고 검토 대기 처리 |
| Backend → Database | 사용자·일기·분석의 트랜잭션 경계가 명시된 쓰기 | 부분 성공을 완료로 응답하지 않고 롤백 또는 보상 작업 기록 |

Frontend와 AI Module은 Database에 직접 접근하지 않습니다. 일기 원문을 외부 AI에 전송할 범위와 마스킹 규칙은 개인정보 검토 전까지 미확정 사항입니다.
